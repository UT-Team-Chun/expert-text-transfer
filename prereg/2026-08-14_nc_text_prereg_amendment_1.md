## 逸脱 1 — null の層別が仕様より粗かった

**凍結仕様**（prereg 26-27 行目）:
> **null**: **borehole ブロック置換**（ボーリング単位で embedding ブロックを
> 入れ替え; 層内順序は保持）、**region×lithology-macro 層内**で置換

**実際に走った実装**: `nc_grouped_null.py:213` の `strata_col: str = "region"`
が既定で、P-T1/T2/T3 の駆動側（`:454`）は `strata_col` を渡していなかった。
`aist_litho_macro_code` は frame に存在したので、使えたのに使われていない。

**影響 — 実測**: 同一条件で両層別を走らせて比較。

| 地域 | strata=region | strata=region×litho-macro | 差 |
|---|---|---|---|
| kanto | −15.533% | −15.800% | −0.27 pp |
| shikoku | −13.034% | −12.928% | +0.11 pp |
| kyushu_okinawa | −11.601% | −11.224% | +0.38 pp |

**≤0.4 pp、符号も地域で不揃い。** 機構的な理由も付く: `aist_litho_macro_code`
は既に baseline の `lt_*` one-hot として入っているので、donor を岩相一致に
制限しても null モデルにとって新情報にならない。

**対応**: `strata_col` を複合層別に対応させ、CLI 既定を事前登録どおりの
`region aist_litho_macro_code` に。**全数値を事前登録どおりの層別で再実行**。
UK には AIST 岩相コードが無いため region 単独に落ちるが、**実際に使われた
層別列を成果物に記録**する（`null_permutation.strata_columns`）。

**なぜ 3 週間気づかれなかったか**: 層別を検証するテストが存在しなかった。
`test_grouped_null.py` に primitive レベルの `test_strata_respected` はあったが、
**駆動側が何を渡しているかを検査するテストが無かった**。

## 逸脱 2 — null が置換になっていなかった（こちらが本質的）

これは仕様の解釈違いではなく**実装の欠陥**である。

**何が起きていたか**: donor をストラタム内の自由な置換で決め、その後
`take = np.minimum(np.arange(len(rows)), len(donor_rows) - 1)` で
**donor のブロック長にクリップ**していた。recipient が donor より長いと、
超過行はすべて **donor の最深層のコピー**を受け取る。

**実測（P-T1 の実母集団、52,806 行 / 4,000 ボーリング）**:

| | 値 |
|---|---|
| 複製行 | **22,547 / 52,806 = 42.7%** |
| 一度も使われない source 行 | **22,547** |
| 同一 source 行の最大再利用回数 | **77** |

**なぜ不正か**: 返るインデックス写像が**全単射でない**。埋め込み行列の置換に
なっていないので、null 腕は観測腕より系統的にテキストの多様性が少ない。
sharp null の下でも観測統計量が null draw と交換可能でなく、**効果量は 0 から
離れる方向にバイアス**する。

**影響 — 実測**（同一条件、25 perm）:

| 地域 | 旧 clipped | 新 全単射 | 水増し量 |
|---|---|---|---|
| kanto | −18.117% | −15.533% | **2.58 pp** |
| shikoku | −14.416% | −13.034% | **1.38 pp** |
| kyushu_okinawa | −12.254% | −11.601% | **0.65 pp** |

3 地域とも同方向。**効果そのものは生き残るが、既報の効果量は過大だった。**

**過大だった量は 2 通りの読み方があり、両方を明記する**（片方だけ引用すると
文書間で矛盾して見えるため）:

| 測り方 | 範囲 |
|---|---|
| **地域ごと**（上表、同一条件 25 perm の A/B 比較） | **0.65 〜 2.58 pp** |
| **campaign の地域平均**（保管済み 1000 perm と再実行 1000 perm の比較） | **0.58 〜 1.36 pp** |

| campaign | 旧（欠陥 null） | 新（全単射 null） | 差 |
|---|---|---|---|
| Japan s42 | −15.247% | −14.031% | +1.22 pp |
| Japan s43 | −14.004% | −13.077% | +0.93 pp |
| Japan s44 | −13.870% | −12.507% | +1.36 pp |
| Japan 全母集団 | −13.252% | −12.677% | +0.58 pp |
| UK | −7.273% | −6.508% | +0.76 pp |

地域平均の方が小さいのは、地域ごとの水増し量が相殺し合うため。**最悪の 1 地域
（kanto の 2.58 pp）と平均（最大 1.36 pp）は別の量**であり、論文本文とマクロは
平均を、本 amendment は両方を引用する。

**対応**: 2 段構成の全単射スキームに置換。
1. **長さ一致ブロック交換** — (stratum, 層数) でグループ化し、2 本以上の
   グループ内で derangement。donor と recipient の長さが構成上一致するので
   rank が正確に対応し、複製も脱落も自己テキストも起きない。
2. **rank 単位の残余処理** — 層数を共有しないボーリングをストラタム単位で
   プールし、rank ごとに derangement。これも全単射。

**カバレッジ（実測）**: 全 text-bearing 母集団で step 1 が region 層別 99.5% /
region×litho 層別 97.6%。500 files/region subsample では 91.1% / 70.3%。

**自己テキスト保持**: ストラタムの残余プールで、ある rank にボーリングが 1 本しか
無い場合のみ発生（0.1〜1.4% の行）。**避けられず、かつ厳密に保守的**（null が
実テキストを持つので効果を薄める方向）。draw ごとに計数し成果物に記録。

**旧実装の扱い**: `legacy_clipped_block_permutation` として、**バイアスを測る
目的だけ**に保存。「これが全単射でないこと」を assert する回帰テスト付きで、
静かな復活を防ぐ。

**なぜ 3 週間気づかれなかったか**: **既存テストが欠陥の挙動を「正しい」として
固定していた**。`test_unequal_block_lengths_clip` は「短い donor はクリップされ、
深い recipient 行は donor の最深行を再利用する」ことを assert していた。
テストが仕様の役を果たしてしまい、欠陥が仕様に昇格していた。当該テストは
全単射性を assert する形に書き換えた。

## 逸脱 3 — 推論の 4 点（仕様には明示が無く、実装が不適切だった箇所）

事前登録は手法名を挙げていたが、実装の細部までは凍結していない。以下は
仕様違反というより**統計的な誤り**であり、監査で指摘され修正した。

| 箇所 | 問題 | 影響（実測） | 対応 |
|---|---|---|---|
| BCa の null 腕 | per-borehole の null loss を最初の `len(seeds)`=**3 draw** しか累積していなかった（点推定は 1000 draw） | 区間が 3 draw 推定に依存 | 全 draw を累積。区間は置換分布の期待値に対するものになる |
| BCa の acceleration | **間引き jackknife**（約 200 点）。`a` は m^(−1/2) でスケールするので \|a\| が √(n/m) 倍に膨張 | nb=4,000 で **2.0 倍**、全母集団規模で約 57 倍。ただし `a`≈0.0022 と小さく区間は ±0.005 pp しか動かず | 全 leave-one-out を閉形式で。ループ不要で高速 |
| fold の p 統合 | **Stouffer は独立を仮定**。leave-one-region-out fold は訓練行の 6/8 を共有し正に従属 → 反保守的 | 定量せず（従属構造の推定が必要）。ただし全 fold が置換下限にあるので Bonferroni でも有意 | **Bonferroni-min と Cauchy 統合**（任意の従属性で妥当）を主。Stouffer は従属性の注記付きで副次 |
| 8 地域 bootstrap | 8 単位の percentile bootstrap を「95% CI」として提示。構造的に under-cover し、実際に全母集団値を覆えていなかった | 覆えていなかった事実そのもの | **記述的ばらつき**に降格。推論は borehole BCa のみ |

## 逸脱 4 — P-T4 の family 構成

事前登録は P-T4 の family を
「leave-project-out / leave-contractor-out / leave-year-out / leave-DTD-out」と
名指ししている。実装は **`client`（発注機関）を追加**し、**`project` は実行
されなかった**。

`project` が実行されなかった理由は実測で確定している: 500 files/region
subsample では 300 行以上のプロジェクトが **1 件しかなく**（上位 8 件は
342〜152 行）、`MIN_FOLD_ROWS = 300` に軒並み掛かって fold が 0 本になる。
全母集団では該当 **920 件**（最大 3,768 行）。**subsample スケールでは原理的に
測定不能**。

**対応**: `client` は事前登録外の追加として明記する（削除はしない —
発注機関を跨ぐ検証は有用で、隠すのは逆に不誠実）。`project` は全母集団で実行。

## 4. 既報値との比較についての訂正

**この campaign 中に私が書いた「効果が強くなった / 弱くなった」という比較は
すべて誤りである。** 論文の既報値 −11.3%（Japan）/ −9.5%（UK）は
**within-lithology-class null**（岩相クラス層内の行シャッフル）に対する値で、
新解析は**別の null**（borehole ブロック置換）に対する値。層別も単位も違う。

実測（`2026-07-04_within_null_v2_*.json`）:

| null | Japan | UK |
|---|---|---|
| global | −19.56% | −9.81% |
| within_region | −19.44% | −9.77% |
| **within_class ← 論文の既報値** | **−11.25%** | **−9.47%** |

さらに baseline も母集団も違う:
- **baseline**: 新解析は granular geology（`lt_*` 岩相 one-hot）+ KNN 空間 prior を
  追加。岩相情報が baseline に入った分、text の伸び代が減る
- **母集団**: 同じ「500 files/region, seed 42」でも旧 3,116 本 / 新 4,000 本で、
  **共通は 174 本**（ほぼ別標本）

**したがって既報値と新値は直接比較できない。** 論文では「同一の推定量を別の
null で測り直した」ではなく「**別の推定量を新たに事前登録して測った**」と
書く。旧値を「アーティファクトだった」と述べることも、
「under-claim だった」と述べることも、どちらも成立しない。

stop clause 2（「P-T3 で |Δ| ≥ 5 pt なら行 null 由来の全数値を隔離」）の判定は
**同一データ・同一 baseline で null の単位だけを変えた対比**に対して行うべきで、
既報値との差に対して行うものではない。その判定は再実行後の P-T3 で行う。

## 再発防止

欠陥が生き延びた原因は共通していた — **成果物が、自分が依存している性質を
記録していなかった**。効果量しか残さない JSON は、その効果量が前提とする
性質を後から監査できない。

導入した対策:
1. **成果物の自己証明**: 各地域ブロックに `null_permutation`（実際に使われた
   層別列 / 全 draw が置換だったか / draw 数 / 3 経路の内訳）。旧コードなら
   `all_draws_bijective` が全 draw で false になるので、**公開 JSON だけで
   新旧を判別できる**
2. **provenance の導出化**: `_provenance.null` はハードコード文字列だったため
   層別変更・Stouffer 降格の後も古い記述を出し続けていた。成果物から導出する
   形に変え、stale になり得る文字列を消した
3. **仕様を守るテスト**: `test_cli_arguments_bind_to_the_real_run_signature`
   （並行編集による半端マージの検出）、`legacy_clipped_block_permutation` が
   全単射でないことの assert、層別が成果物に記録されることの assert
4. **欠陥を固定していたテストの書き換え**: 挙動を assert するテストは、
   その挙動が正しいことを保証しない。今回はテストが欠陥を仕様に昇格させていた
